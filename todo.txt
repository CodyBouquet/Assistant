USING IT DAY TO DAY
=====================================================================

- Check balances / bills / recent transactions: open the Dashboard, or
  text the assistant ("what's my balance?", "what bills this week?").

- Ask affordability questions:
    "can I squeeze $500 for concert tickets this month?"
  Claude pulls balances, upcoming bills, and spending pace to answer.

- Log cash or gift money that won't hit your bank:
    "spent $12 cash on lunch at Chipotle"
    "got $200 from mom for my birthday"
  Claude auto-logs it and replies with a one-line confirmation. These
  entries roll up into budgets alongside Plaid transactions.

  To undo the last manual entry, text:
    "undo that" or "delete that last one"

  You can also view, add, edit, or delete manual entries manually at
  /manual in the web UI.

- Proactive texts: the daily cron at 8am US Central scans for bills due
  soon, categories over budget, and unusual transactions. It only texts
  you when there's something actually worth saying.

=====================================================================
WHAT THE CODE ALREADY DOES FOR YOU
=====================================================================

- Plaid access tokens encrypted with AES-256-GCM at rest
- Hard sign-in allow-list (ALLOWED_EMAILS); everyone else is rejected
- Strict phone allow-list for SMS; unregistered numbers get silent
  responses (no existence leak)
- Twilio webhook signature validation in production
- Rate limiting on chat + webhook + auth endpoints
- Constant-time secret comparison on cron endpoints
- Security headers: HSTS, CSP, X-Frame-Options, X-Content-Type-Options,
  Referrer-Policy, Permissions-Policy
- Redaction of sensitive fields in error logs
- Zod validation on all JSON API input
- Drizzle ORM (parameterized queries — no SQL injection)
- HttpOnly, Secure, SameSite cookies (Auth.js defaults in production)
- No "dev bypass" paths — the same auth runs locally and in production

=====================================================================
WHEN YOU GET STUCK
=====================================================================

- Build fails on Railway: read the full build log, not just the summary
- "Unauthorized" on sign-in: your email isn't in ALLOWED_EMAILS
- Magic link never arrives: check Resend dashboard > Logs
- Plaid Link won't open: browser console for CSP violations (might need
  to adjust next.config.ts if Plaid adds new domains)
- Twilio replies are generic/broken: check Railway logs during a test
- Cron does nothing: verify the CRON_SECRET env var is set on Railway
  and that the cron commands reference $CRON_SECRET (with the $)
